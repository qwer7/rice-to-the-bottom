## Локальный запуск

```sh
npm install
npm run dev -- --host 0.0.0.0
```

На компьютере используйте Local-адрес Vite, на телефонах в той же Wi-Fi сети —
Network-адрес. `localhost` на телефоне указывает на сам телефон.
Сначала выберите «Доска результатов» → «Создать хаб» и сохраните постоянный ключ.
Главный игрок входит по ключу, выбирает имя и создаёт лобби во вкладке «Управление». Остальные
выбирают «Игрок», вводят код и собственные имена. Большой экран подключается
через «Доска результатов» по тому же коду, без имени и игрового места.

## Хранение и права

- `game_sessions` — публичное состояние комнаты, версия и только последнее раскрытие.
- `game_seats` — постоянная связь пользователя и игрового места.
- `game_viewers` — пользователи, подключившие доску по коду.
- `game_player_private` — руки, колоды, сброс, выложенные карты и лимит обмена.
- `game_influence_choices` — таблица старого прототипа, в версии 2 не используется.

Все таблицы защищены RLS. Приватные таблицы не имеют политик чтения для браузера.
Сервер отдаёт только руку текущего игрока без колоды и сброса. Главный игрок
видит только свои закрытые карты, как и остальные участники.

`commit_v3_game` сохраняет публичное состояние, карты и новые места в одной
транзакции. Версия комнаты проверяется под блокировкой строки. При устаревшей
версии функция возвращает пустой результат; обработчик перечитывает состояние
и повторяет действие. Это предотвращает потерю одновременных ходов.
`read_v3_game` возвращает согласованный снимок и только личную руку.
Обе SQL-функции доступны только `service_role`, который остаётся на сервере.

## Обновление v3: атомарные ходы и постоянные хабы

Добавлена миграция `20261022000002_atomic_turns_and_hubs.sql`. Применить после трёх предыдущих миграций, затем обновить все три Edge Functions. Клиент и функции используют `schemaVersion: 3`; старые комнаты нужно заменить новыми через хаб.

`game_hubs` закрыта RLS без клиентских политик. Постоянный случайный ключ возвращается только при создании хаба; на сервере хранится SHA-256. Открытый код хаба позволяет подключить доску, но не управлять игрой. Вход по ключу атомарно назначает одного управляющего и отзывает управление у предыдущего подключения. Ключ и метаданные хаба сохраняются локально в браузере создателя; при очистке данных браузера нужен ранее сохранённый ключ.

`create_hub_room` атомарно создаёт комнату, место главного игрока и его закрытую колоду. Перед созданием следующего лобби текущее необходимо закрыть. `commit_v3_game` использует блокировку и проверку версии с возвратом пустого результата при конфликте, поддерживает удаление места игрока и повторно проверяет управляющего внутри транзакции. Прямой вызов этих процедур разрешён только service_role.

В `game_player_private.payload` находятся рука, колода, сброс, общий счётчик обменов, ожидающий полный ход и идентификатор последней отправки. `read_v3_game` возвращает только собственную руку, выбранную карту, счётчик и собственный ожидающий ход. Колоды и чужие черновики не доступны клиенту. Публичное состояние содержит только прежние финансовые результаты и готовность, пока последний игрок не завершит ход. Локальный черновик сохраняется отдельно для комнаты, игрока и раунда; перезагрузка того же устройства его восстанавливает.

Протокол игрока: `submit-turn` с `{round,id,trades:[{companyId,action}],cardId}`, либо `exchange-card` с `{round,cardId,selectedCardId}`. Покупка, продажа, смена этапа и выбор карты не вызывают сервер. Старые отдельные действия buy/sell/finish-turn на сервере больше не принимаются.

## Короткие ключи — 23 октября 2026

Миграция `20261023000000_short_hub_keys.sql` добавляет закрытый резервный хеш старого ключа. Обновлена функция `create-room`: новые хабы получают ключ из восьми символов, существующие преобразуются при синхронизации с сохранённым длинным ключом или при входе по нему. Старый ключ остаётся действующим. Короткий ключ можно вводить строчными буквами, с пробелами или дефисом между группами. В браузере есть кнопка копирования; в базе оба ключа представлены только хешами. Общие правила нормализации и генерации находятся в `_shared/hubKey.ts` и должны включаться в Dashboard-бандл.

## Доски с первым игроком-лидером

Миграция 20261023000001_display_lobbies.sql применена через Dashboard. Добавлены mode у game_hubs, открытие display-лобби без игрока и атомарный перезапуск. host_user_id может быть NULL только до входа первого игрока; commit_v3_game назначает первого участника лидером под той же блокировкой строки и проверкой версии, что и добавление места. open_display_lobby идемпотентна для одного владельца доски, создаёт/восстанавливает её активную комнату. restart_display_lobby повторно проверяет текущего лидера в транзакции, закрывает прежнюю комнату и создаёт следующую. Прямое выполнение процедур доступно только service_role. Обновлены create-room и game-action. Проверены конкурирующие входы, повторные открытия доски, ограничения управления и переход доски к новой комнате.
